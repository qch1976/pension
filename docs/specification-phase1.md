## 1. 范围与目标

1. 【REQ-01-SCOPE-000】新增**选项页**，提供「基本计算」与「方案比较」两个入口。
2. 【REQ-01-SCOPE-001】「方案比较」支持用户添加 **1~3 个方案**，逐方案复用 Phase-0 引擎计算月养老金及比较指标。
3. 【REQ-01-SCOPE-002】方案间差异**仅限 3 项**：退休年月、2026-09 起月缴费 Z 值、2026-09 起缴费性质；历史数据（≤2026-08）各方案共用、只录一次（裁定 Q1）。
4. 【REQ-01-SCOPE-003】系统比较并渲染：**P月、R续、回本月数（含利率）、ROI**。
5. 不在范围：养老待遇年度调整；真实缴费金额核定；修改 Phase-0 任何计发公式；方案间差异化历史数据。

## 2. 术语与符号（全文统一，无歧义）

| 符号 | 定义（批准口径） |
|---|---|
| **P月** | 方案退休时按月领取的**月基本养老金合计**：**P月 = J基础 + J账户 + J过渡（中人）**，= Phase-0 结果页 `月合计`。（裁定 Q2：客户在 Phase-1 所称「J基础」即此 P月；全文统一用 **P月**，J基础 仅保留 Phase-0「基础养老金分项」含义） |
| J基础 / J账户 / J过渡 | Phase-0 三分项；J过渡 = G同 + G实 |
| **R续** | 2026-09（含）起至本方案退休前一月，**个人实际负担**的养老保险费总额，逐月汇总 |
| **回本月数** | 以 R续 最小方案为基准，候选方案在**基准养老金冲抵（Q4）**后，净多缴被追回所需月数（含利率折算） |
| **ROI** | 投入产出比 = (P月 − P月基准) / R续；P月基准 = 该**方案自身退休年龄**下、2026-09 起 0 投入（停保）所得月养老金（裁定 Q5） |
| Z | 方案参数：2026-09 起目标月缴费指数，0.60~3.00 |
| C_m / B_m | 月指数分母（2026=12116）/ 月缴费基数，**B_m = Z × C_m**（裁定 Q9） |
| r / i | 回本月数折算年利率（用户可输、默认 0.0%）；i = r/12（月利率）。**r=0 为不计息**（裁定 Q6） |

## 9. 比较计算模型

### 9.1 P月（REQ-01-CAL-000）

P月_k = Phase-0 `pension.total`（月额，2 位小数）；同时保留 J基础/J账户/J过渡 三分项供下钻。跨 2027 及以后未公布年度时，**C平/C_m 沿用现值（C平=12049、C_m=12116）并统一打【预估】角标**（裁定 Q7；与 Phase-0 spec §4.8 一致）。

### 9.2 R续（REQ-01-CAL-001）—— 个人负担口径（Q3，书面写明）

| 缴费性质 | 每月个人负担 | 政策依据 |
|---|---|---|
| 企业职工 | **B_m × 8%**（单位缴费不计个人负担） | 京政府令183号第19条；国发〔2005〕38号 |
| 失业灵活就业 | **B_m × 20%（全额自担，其中 8% 入个人账户）** | 183号令第19条；北京市灵活就业参保口径 |

```
R续_k = Σ_{m=2026-09 … 退休前一月} B_m × rate_k
      = Σ Z_k × C_m × rate_k        rate_k=0.08(企业)/0.20(灵活)
```

逐月计算、中间不舍入、展示 2 位；结果页同时展示缴费月数与月负担额。

### 9.3 回本月数（REQ-01-CAL-002）—— 冲抵口径（Q4，已数值验证）

设基准方案 **b = argmin(R续)**（用户方案中 R续 最小者）；候选 k；以 2026-09 为月序 0，b、k 的退休前一月为 T_b、T_k（T_b ≤ T_k）。i = r/12。

**（1）逐月净差额现金流（b 退休后领取的养老金直接冲抵 k 的多缴）：**

```
d_m =  B_m^k×rate_k − B_m^b×rate_b        0 ≤ m ≤ T_b   （并存缴费期）
d_m =  B_m^k×rate_k − P月_b               T_b < m ≤ T_k （b 已按月领养老金，冲抵 k 独缴）
```

**（2）k 退休时点净多缴终值：**

```
FV_k = Σ_{m=0..T_k} d_m × (1 + i)^(T_k − m)
```

**（3）月数判定（三分支）：**

- **分支A — 退休前已抵回**：滚动 b 退休后的净余额 `A_m = Σ_{j=0..m} d_j(1+i)^(m−j)`；若存在最小 m（T_b < m ≤ T_k）使 **A_m ≤ 0**，回本发生在 **b 退休后第 (m − T_b) 个月**（k 退休前），回本月数记该值并标注「退休前已抵回」。
- **分支B — 退休后抵回**：若 A_{T_k} = FV_k > 0，k 退休后每月相对多领 ΔP_k = P月_k − P月_b：

```
FV_k = ΔP_k × [1 − (1+i)^(−n)] / i
⇒ n = − ln(1 − FV_k × i / ΔP_k) / ln(1 + i)
r=0（不计息）：n = FV_k / ΔP_k
```

展示小数月并向上取整到整月。
- **分支C — 无法抵回**：ΔP_k ≤ 0，或 `1 − FV_k·i/ΔP_k ≤ 0`（含息年金现值不足）⇒ 标注**「该利率下无法抵回」**。

> **数值验证（node，2026-09-30）**：玩具例（b 月缴 800、缴 12 月退休领 3000；k 月缴 1000、缴 24 月退休领 4200）：
> r=0：FV净 = −21600 → **分支A，b 退休后第 2 个月即抵回**；r=6%：FV净 = −22051.85，同样退休前抵回；
> 冲抵不足例（b 领 900、k 领 1100）：FV净=3600 → **分支B，n=18 月**；
> 年金现值不足例（FV=100000、ΔP=500、i=0.5%）→ **分支C，Infinity**。公式与判定全部回代成立。

**（4）利率列（REQ-01-CAL-003，Q6）**：回本月数利率用户可输入、**默认 0.0%**；结果表**固定展示「0%」一列**，并并排展示用户给定利率一列（用户给 0 时两列相同）。

### 9.4 ROI（REQ-01-CAL-004）—— 随案 0 投入基准（Q5）

- **基准定义**：对**每个方案 k 各自的退休年龄 T_k**，构造「2026-09 起 0 投入（停保）」情形（历史/视同/账户锚点不变），由 Phase-0 引擎计算 **P月基准_k**；该基准为系统**内部逐方案生成，不占用用户 3 个方案名额**。
- 公式：

```
ROI_k = (P月_k − P月基准_k) / R续_k        （无量纲，保留 4 位，并展示百分比）
```

- **不足年限阻断**：停保导致该退休年龄下不满足最低缴费年限时，P月基准 无法按月领取 ⇒ 该方案 ROI **不计算**，红字提示「0投入基准不满足按月领取条件，ROI不可用」，并不参与 ROI 排名。
- 基准区分（UI 须明确）：**回本月数基准 = R续最小用户方案**；**ROI 基准 = 逐方案内部 0 投入情形**。
