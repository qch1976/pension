### 2.2 核心结论

- **计算主干质量较好**：S1–S4 的 Z实指数、N应缴、N同、N实98、J基础、G同、G实、官方/固定利率 R储 与独立 oracle 及手工推导全部一致（57 项 TC-C 断言通过 56 项）；spec 12.2–12.4 政策数据表（计发基数 9910/10534/11082/11525/11883/12049、历年利率、M 计发月数全表、旧口径工资表）与代码逐项核对一致。
- **输入校验层是最大短板**：NaN（UI 空输入可达）、负值、矛盾时间均可穿透，其中 1 条直接造成输出总额为 NaN。
- **UI 集成层存在致命伤**：结果页 WXML 模板语法错误使整个结果页无法编译；政策溯源弹窗键值不匹配使 FR-12 完全失效。
- **一处年度语义错位（BUG-009）影响面最大**：所有需要补录 1992–1995 缺口分母的用户，按界面提示录入后指数整体错配，且 1995 年仍被判缺口计 0，属于"静默算错钱"。

## 3. 缺陷清单（分级：Blocker / Major / Minor）

### 3.1 Blocker（1 个）

#### BUG-001 ｜结果页 WXML Mustache 不配对，结果页无法编译渲染（主流程阻断）

| 项 | 内容 |
|---|---|
| 用例 | TC-U-001（P0，WALK+编译） |
| 现象 | `pages/result/result.wxml` 第 29 行：`…G实(¥{{r.intermediates.G实})，仅中人享有…`——该行 `{{` 出现 2 次、`}}` 仅 1 次，缺少一个 `}` |
| 预期 | 模板标签全部配对，微信开发者工具编译通过，结果页正常渲染 |
| 实际 | 静态扫描可确认 WXML 编译期必报错（Expected FOO / unexpected token），结果页白屏或编译失败；首页→测算→结果页主流程不可用 |
| 复现 | 微信开发者工具打开项目 → 编译 → 首页任意合法输入 → 点"开始测算"跳转结果页；或直接编译即报 WXML 语法错误 |
| 定位 | `pages/result/result.wxml:29`，`{{r.intermediates.G实}` 改为 `{{r.intermediates.G实}}` |
| 修复建议 | 补全 `}}`；在 CI 增加 WXML 标签/Mustache 配对扫描，防止复发 |
| 回归点 | 修复后结果页全部数据卡正常展示，TC-U-001 与全部 UI 人工用例（TC-U-012～014）方可执行 |

#### BUG-003 ｜手工视同月数留空（NaN）穿透，输出总额 NaN

| 项 | 内容 |
|---|---|
| 用例 | TC-F-015（P0，AUTO） |

| 输入 | `deemedMonths: NaN`（S1 其余输入同 test-cases 1.1） |

#### BUG-004 ｜视同月数负值采信、与参加工作时间矛盾不截断（违反 E-08/spec 7.2）

| 项 | 内容 |
|---|---|
| 用例 | TC-F-016（P1）、TC-F-018（P0） |
| 复现 | ① `deemedMonths:-5` → `N同=-0.4167`，N实+同 虚减；② `workStartYM:'2000-01'` + `deemedMonths:600` → `N同=50` 年全额采信，`G同/J基础` 巨额虚增，`eligible=true` |
| 预期 | 负值拒绝（spec 7.2：0～600）；按 E-08 视同月数不得超过 `[workStart,1992-09]` 月数，矛盾时截断到 1992-09 并黄字提示；1992 年后参加工作者视同必为 0 |
| 定位 | `pensionEngine.js` deemedMonths 分支：仅有上限/无下限/无与 workStart 一致性校验（spec E-08 明确要求截断） |
| 修复建议 | `deemed = Math.max(0, Math.min(raw, 1992-09 与 workStart 之间月数))`，手工值超过截断值时 warning 并在 UI 黄字提示 |

#### BUG-005 ｜固定年利率空输入（NaN）静默按 0% 计息

| 项 | 内容 |
|---|---|
| 用例 | TC-F-014（P1，AUTO） |
| 复现 | 计息方式选"固定年利率"，输入框留空：`fixedRate=NaN`。校验 `typeof r==='number' && r>=0 && r<=24` 对 NaN 返回 false 却未进入报错分支；计息处 `if(r>0)` 对 NaN 为 false，静默免息 |

| 预期 | spec 7.2：固定利率为必填项，空值阻断并提示 |

#### BUG-007 ｜"半年简化"计息口径下，退休当年缴费利息未按月折算

| 项 | 内容 |
|---|---|
| 用例 | TC-C-404（P1，AUTO，唯一失败的计算正确性用例） |
| 场景 | S3 输入，`interestMode:'fixed', fixedRate:0.04, intraYearMethod:'half'`，2025-09 退休（退休当年仅 1–8 月） |
| 预期（spec 4.6） | "退休当年只计到退休前一月，**同规则按月折算**"：2025 利息 = 年初余额×4%×8/12 + Σ 缴费×4%×对应月权重 = **10609.69** |
| 实际 | **10556.36**：年初余额部分已正确×8/12，但当年缴费仍按固定 0.5 年权重（=800×4%×0.5×8=128），少计 53.33 元 |
| 影响 | 所有年中退休 + 选择半年简化口径的用户，退休当年利息偏小；本金越大、利率越高偏差越大 |
| 定位 | `pensionEngine.js` 账户年循环：退休年分支对 `intraYearMethod==='half'` 未特殊处理缴费权重 |
| 修复建议 | 退休当年缴费权重统一改为 `(12-m0)/12`（与 monthly 一致），half 仅作用于完整历史年度 |

#### BUG-008 ｜个人账户月入账额逐月 round2 后累加，违反 spec 4.7"中间过程不舍入"

| 项 | 内容 |
|---|---|
| 用例 | TC-I-301（P0，AUTO） |
| 证据 | 20 个月、基数 7056.6：精确月入账 564.528，精确 R储=20×564.528=**11290.56**；引擎逐月 `round2(564.53)` 累加=**11290.60**，单笔场景差 0.04。S2（333 月）因历史基数多为整值偏差未显化，但非整基数+30 年+复利滚动下偏差会累积，超出 NFR-03 的 0.01 容差 |
| 预期 | spec 4.7：金额中间计算不舍入，仅展示层保留 2 位 |
| 定位 | `pensionEngine.js` 月明细构造处 `principal8: round2(base*0.08)`，账户累加复用了该舍入值 |
| 修复建议 | 内部累加用原始值，仅在 `monthlyDetails` 展示字段做格式化 |

### 3.4 观察项（不计缺陷，提请产品/评审确认）

1. **spec 内部表述歧义**：4.6 文字"次月起按月折算"与同节明确的权重公式（退休年 1–8 月权重 (12+…+5)/12）在措辞上易误解；代码遵循公式，测试以公式为准。建议 spec 下一版补一句算例。
