## 6. 观察记录（按 Manager 指示：仅记录，不开票、不改码）

### 6.1 entryMode 切换会携带陈旧 `data.segments`
- **现象**：文件导入后 `entryMode='year'`，但页面 `data.segments` 仍是导入前的遗留数组（可含旧首段、且不含正确自动段）。若此时把 `entryMode` 手工改为 `'month'`，`buildInput()` 会改读这份陈旧数组，与 compare 侧不一致（我最初据此误判"两页首段解析不一致"；实际两页导入层共用 `buildInputLike`，输出一致）。
- **复现**：导入 e7-my1.txt → `setData({entryMode:'month'})`（不清 segments）→ `buildInput()` → 首段/段集与 year 模式不同。
- **影响面**：仅影响 year→month 切换瞬间；正常用户在界面点「月录入」时产品是否重建 segments 需产品确认。不阻断本次验收。
- **建议**：切模式时用 `expandYearRows(yearRows)` 重建 `segments`。

### 6.2 夹具复制陈旧副本（我的操作缺陷）
- **现象**：`importFixture` 只从 `docs/customer_usecases/` 读，我早期手工把 `temp/bug31-case-files/` 的文件复制过去，复制的是**旧 3 列版**（缺「年内起始月份」「缴费身份」），导致一度把首段差异误判为产品缺陷。
- **根因**：复制未校验列数/版本。
- **已纠正**：自 `828ccd3`/`5a42fba` 起仓库内已为 sandbox 权威 5 列版，**不再手工复制**；本次全部验收直接读仓库权威夹具。
- **改进**：用夹具前先校验 bytes/行数/列数=5。

### 6.3 清空 retireYM 后连续切换身份不重算（0018 边界行为，非阻断）
- **现象**：清空 `retireYM` 后选「女」得 2034-11；随后再切「女干部」，因 `retireYM` 已非空（`refreshDefaultRetire` 有"已存在则不覆盖"的 0018 修复），故仍显示 2034-11，未更新为 2039-06。仅"先清空再选身份"可正确得到 2039-06。
- **影响面**：不阻断计算；符合 0018"保留用户/文件值"的设计取向，属预期行为边界。
- **建议**：如项目主要求切换身份时联动重算，可加"身份变更且 retireYM 未被手选"时重算的规则；本期不改。
